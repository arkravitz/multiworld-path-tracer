# Photon-Driven Neural Radiance Caching implementation notes

Reviewed 2026-11-15 against Stamm, Kneiphof, Klein, I3D Companion 2026, DOI [10.1145/3807895.3807923](https://doi.org/10.1145/3807895.3807923), the supplied three-page paper, and the [author implementation](https://github.com/julcst/photon-nrc) at commit `e02a99d5e3a54d055d0c315e36f363211d09e43e`. The estimator below is SPPC, not a generic photon-map teacher. Hardware and neural-network substitutions must be described separately from estimator fidelity.

## Exact progressive state and target

Each persistent query stores position, normal, material, outgoing direction, revision, emitted-photon count at birth, and **two independent** progressive states `(N, r, Phi)`, one global and one caustic. `N` is floating point. Each frame has separate temporary accumulators `(M, deltaPhi)` with `M` integer.

For each of the two states independently, if `M > 0`:

```text
alpha = 2/3
Nnew = N + alpha*M
k = Nnew / (N + M)
rnew² = r²*k
Phinew = (Phi + deltaPhi)*k
```

If `M == 0`, leave the state unchanged. Crucially, include current flux **before** multiplying by `k`; the PDF text extraction interleaves the equations and hides this. This is explicit in `QueryState.applyRadiusReductionGlobal/Caustic`. The outgoing radiance target, excluding emission, is:

```text
n = emittedNow - emittedAtBirth
Lo = (PhiGlobal / rGlobal² + PhiCaustic / rCaustic²) / (pi*n)
```

Use both radii after reduction in this expression. Guard `n == 0`, invalid queries, NaNs, and counter overflow. Do not replace `n` with stored photon count, accepted matches, query age alone, or the global progressive `N`. Sources: [progressive states and normalization](https://github.com/julcst/photon-nrc/blob/e02a99d5e3a54d055d0c315e36f363211d09e43e/Source/RenderPasses/AccumulatePhotonsRTX/Structs.slang), [target finalization](https://github.com/julcst/photon-nrc/blob/e02a99d5e3a54d055d0c315e36f363211d09e43e/Source/RenderPasses/AccumulatePhotonsRTX/FinalizeBuffer.cs.slang).

`deltaPhi` is **outgoing**, already multiplied by the query BSDF. The author code obtains Falcor's BSDF-times-cosine evaluation and divides by the incident cosine, so the accumulated quantity is `photonFlux * f_s(wi, wo)`, without another cosine. For this renderer's Lambertian receivers, use `photonFlux * albedo / pi`. The density area contributes the *other* `pi` in `Lo` above. If using existing albedo-demodulated network labels, accumulate `photonFlux/pi` instead and multiply network output by albedo once at inference, or accumulate outgoing flux and divide target by albedo safely. Do not apply albedo twice. Source: [stochastic accumulation](https://github.com/julcst/photon-nrc/blob/e02a99d5e3a54d055d0c315e36f363211d09e43e/Source/RenderPasses/AccumulatePhotonsRTX/StochasticQuerySearch.rt.slang).

## Ring, query generation, and emission lifetime

Trace ordinary camera BSDF paths to the first diffuse vertex; preserve the camera prefix throughput and emission. Uniformly subsample inference query records to replace the oldest ring slots. Each frame advance a ring head by `floor(R*Nq)` and replace that contiguous wrapped interval, with `R=0.02` in the caustic examples (approximately 50-frame lifetime). On successful replacement increment/change revision and reset **both** states and the birth counter. Existing queries keep accumulating and shrinking, even if not replaced.

The author subsampler retries invalid source queries and otherwise retains the old destination; failed replacement therefore need not reset state. At initialization, explicitly seed all valid slots or maintain validity masks rather than training on uninitialized slots. Source: [subsampling shader](https://github.com/julcst/photon-nrc/blob/e02a99d5e3a54d055d0c315e36f363211d09e43e/Source/RenderPasses/QuerySubsampling/QuerySubsampling.cs.slang), [ring advancement](https://github.com/julcst/photon-nrc/blob/e02a99d5e3a54d055d0c315e36f363211d09e43e/Source/RenderPasses/QuerySubsampling/QuerySubsampling.cpp).

The steady global counter counts **emitted light paths**, not photon deposits. A single light path can deposit multiple photons. Record birth before tracing that frame's photons; add the frame's emitted count before finalizing targets. The author code does exactly this, so newborn queries include this frame in both numerator and denominator. Ordinary frame clears must not reset cumulative emission or persistent query states. Source: [frame ordering and cumulative counter](https://github.com/julcst/photon-nrc/blob/e02a99d5e3a54d055d0c315e36f363211d09e43e/Source/RenderPasses/AccumulatePhotonsRTX/AccumulatePhotonsRTX.cpp), [revision resets](https://github.com/julcst/photon-nrc/blob/e02a99d5e3a54d055d0c315e36f363211d09e43e/Source/RenderPasses/AccumulatePhotonsRTX/Preparation.cs.slang).

## Photon tracing and search

The published method traces light paths through diffuse **and** specular interactions and stores at every suitable diffuse hit, including first-hit/direct photons. Continue the light path after a diffuse deposit. `isCaustic` is initialized false, and then set from the **previous sampled lobe** (`Specular | Delta`); a diffuse event resets it. It is not a permanent "has ever touched glass" flag. At a receiver after a delta chain it is caustic; after a diffuse segment it is global. Importance/flux transport must not carry the radiance eta-squared transmission factor. The existing renderer already gets this distinction right for its caustic light tracer.

For global photons only, survival is `s=1-pReject=0.3`. Reject with probability 0.7 and multiply surviving stored flux by `1/s`; do **not** additionally reduce `n` or rescale counts by `1/s`. Caustic flux is unchanged. Any directional/light selection proposal must also have its full inverse proposal density in emitted flux. A proposal that targets only glass has no support for global indirect illumination; retain a full-support component when reusing existing guided emission. Sources: [photon trace and correction](https://github.com/julcst/photon-nrc/blob/e02a99d5e3a54d055d0c315e36f363211d09e43e/Source/RenderPasses/TracePhotons/TracePhotons.rt.slang), [paper graph and scene settings](https://github.com/julcst/photon-nrc/blob/e02a99d5e3a54d055d0c315e36f363211d09e43e/Source/Testbeds/PhotonNRCPaper.cpp).

Use a uniform top-hat radius test, selected from the query's global/caustic radius according to the photon class. A cone kernel inherited from the old caustic gather changes the method. The paper rejects normal deviations above 60 degrees. The source uses `abs(dot(queryNormal, photonNormal)) >= cos(60deg)` and optional instance rejection. With this renderer's consistently oriented receiver normals, `dot >= 0.5` is a reasonable stricter adaptation, but record that difference. Do not inherit the old gather's `dot > 0.9`, thin planar slab, or image-space splat as if they were the paper's query-ball estimator.

The preferred author traversal represents queries as balls, photons as infinitesimal rays. Collect a uniform reservoir of at most three matching query IDs per photon, and defer atomics until traversal completes. If `H` eligible query matches were visited and `m=min(H,3)` were retained, multiply each retained outgoing flux by `H/m`. The author increments `M` by **one** per retained match, not `H/m`, and applies reservoir weight to flux only. Applying weight to both flux and count is a different progressive-radius process. Source: [query search](https://github.com/julcst/photon-nrc/blob/e02a99d5e3a54d055d0c315e36f363211d09e43e/Source/RenderPasses/AccumulatePhotonsRTX/StochasticQuerySearch.rt.slang), [reservoir](https://github.com/julcst/photon-nrc/blob/e02a99d5e3a54d055d0c315e36f363211d09e43e/Source/RenderPasses/AccumulatePhotonsRTX/Reservoir.slang).

Source caveat: `Reservoir.addSample` increments its seen count after selection and uses `N/n` for replacement, whereas standard uniform reservoir sampling with the old seen count requires `N/(n+1)`. Implement standard Algorithm R (`seen++`, choose integer uniformly in `[0,seen)`, replace when `<3`) to realize the paper's stated *uniform* reservoir. This intentionally corrects an apparent off-by-one in the released source.

## Inference partition in this codebase

The paper's SPPC target includes **all surface scattering**: global/direct plus caustic. At the first diffuse camera hit, terminate and use `prefixEmission + prefixThroughput * predictedLo`. There must be no additional direct NEE, old caustic splat/gather, or diffuse continuation after that hit; each would overlap the network target. Emission at the query itself remains in the camera prefix. Delta camera paths remain explicitly traced. Source: [camera queries](https://github.com/julcst/photon-nrc/blob/e02a99d5e3a54d055d0c315e36f363211d09e43e/Source/RenderPasses/TraceQueries/TraceQueries.rt.slang), [camera transport](https://github.com/julcst/photon-nrc/blob/e02a99d5e3a54d055d0c315e36f363211d09e43e/Source/RenderPasses/TraceQueries/Query.slang).

Current `src/shaders/caustics.wgsl` traces only specular chains until their first diffuse hit, omits direct deposits, resets photons per frame, gathers a fixed cone kernel, and splats visible caustics separately. Those are unsuitable as SPPC targets without replacement. Current `trace.wgsl` adds `caustic_estimate` before NRC, uses a spread/depth termination heuristic, and separately adds `caustic_visible` after tracing. Disable those overlapping contributions in SPPC mode, and terminate at the first diffuse query even for directly visible floor receivers. Current `nrc.wgsl` trains on short camera-derived teacher records with optional bootstrapping; SPPC mode instead trains on persistent photon query targets and must not bootstrap those labels from its own prediction.

The world-switching transport modes are an additional model beyond the paper. Independently traced fixed-world photons do not train arbitrary mixed-world transport. Scope the faithful mode to the selected fixed glass world (and/or independent A/B fixed-world display); do not claim mixed-world equivalence without a light-side transport derivation.

For a two-world query pool, reject different-world matches before reservoir insertion. The paper uses globally bounded paths (the benchmark photon maximum is eight bounces), but does not encode this renderer's remaining-depth feature. To preserve this renderer's finite-depth reference, store the camera prefix length with each query and the light prefix length with each photon, and reject matches whose combined path exceeds the selected maximum depth. Define segment counts consistently to avoid an off-by-one at direct lighting. Do this eligibility test before incrementing the reservoir's seen count. A full radiance-cache interpretation can instead remove the finite combined-depth target, but that is a different reference comparison.

## Faithful Metal adaptation and parameters

On M1, replace RTX query-ball traversal with a software hash grid **of queries**. Use a counting-sort/scatter grid, enumerate neighboring cells for each photon, test the selected actual radius and normals, and feed all eligible matches to the same three-query reservoir. Hash collisions must be checked against the actual cell; no arbitrary bucket caps or duplicate query visits. A cell width at least the maximum initial radius means a 27-cell search around the photon covers all query centers. Per-query radii still shrink independently. Clear frame accumulators only, and finalize query states in a separate dispatch after collection. Float CAS atomics already present in this project can accumulate selected flux without requiring float-atomic extensions. This preserves SPPC's estimator and query reservoir while changing its acceleration backend; it cannot inherit the RTX performance claim.

The paper's glass preset is `Nq=32768`, `Np=524288`, `R=0.02`, `alpha=2/3`, `rGlobal=0.06`, `rCaustic=0.03`, global rejection 0.7, one training update per frame with batch 32768. Scene units matter: choose radii relative to this scene's scale and report them. Smaller budgets are configurable engineering adaptations, not the published timing configuration. The author network uses two hidden layers of width 64, hash-grid position features, directional spherical harmonics, material features, relative luminance L2, Adam (learning rate 0.01, beta2 0.99), EMA 0.95. This project's width-32 triangle-wave MLP and optimizer differ; retain only with an explicit architecture-adaptation note. Source: [network configuration](https://github.com/julcst/photon-nrc/blob/e02a99d5e3a54d055d0c315e36f363211d09e43e/Source/RenderPasses/NRC/NRC.cpp).

The author's optional network factorization divides outgoing target by `(diffuse+specular+0.01)` and restores that factor at rendering; it is a conditioning choice, not a second irradiance conversion. This renderer can consistently use its existing diffuse-albedo factorization instead. Source: [factorization](https://github.com/julcst/photon-nrc/blob/e02a99d5e3a54d055d0c315e36f363211d09e43e/Source/RenderPasses/NRC/FactorizeOutput.cs.slang).

Exact author encoding configuration: 18 raw floats (position 3, roughness 1, outgoing direction 3, normal 3, diffuse 3, specular 3). Normalize position by the scene AABB to `[0,1]^3` and map directions/normals to `0.5*(1+v)`. Position uses 16 trainable hash-grid levels with two features per level, log2 table size 19, base resolution 16, level scale 2, linear interpolation (32 encoded values). Roughness uses four-bin OneBlob (4), outgoing and normal directions each use degree-three spherical harmonics (9 each), and both albedos use identity (6), giving 60 encoded values total. Hash-grid features are trainable and likely materially affect sharp-caustic representation; increasing only MLP width does not reproduce them. Adam's exact other defaults are beta1 0.9, epsilon `1e-15`, L2 regularization `1e-6`; factorization and JIT fusion default true. These are implementation defaults confirmed in `NRC.cpp`/`NRC.h`, beyond the three-page paper's algorithm description.

A nonzero sky/environment must either be sampled by light emission and enter the global photon target, or be represented as a separately partitioned camera estimator. Silently training only emissive-surface photons drops environment scattering that current `trace.wgsl` includes. For an initial controlled comparison, use the same black environment in SPPC and the path-traced reference.

## Focused validation

Verify one deterministic query update numerically, including `M=0`, new-query first frame, and independent global/caustic radii. Check emitted denominator with photon paths producing zero, one, and several deposits. On a diffuse direct-only scene, compare target normalization to camera NEE to catch the two-pi/albedo errors. Compare reservoir-enabled accumulation statistically to full query enumeration in a dense overlapping-query fixture; compare rejection 0 versus 0.7 at equal emitted budgets. Inspect raw SPPC query targets before judging the neural image. Finally compare equal-time glass renders against a sufficiently converged path tracer and report error, frame time, query budget, photon budget, radii, and training time; the paper itself warns about edge bias, lag, and scene-dependent tuning.
